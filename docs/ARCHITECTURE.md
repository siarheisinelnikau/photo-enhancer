# Architecture

The Windows host uses egui 0.33.3 with `egui_software_backend` 0.0.2 for CPU rasterization and `softbuffer` 0.4.8 for Win32 GDI presentation. OpenGL/glow/glutin and wgpu are absent from the active Windows dependency graph. This is a software renderer with a bitmap presenter; it does not disable Windows desktop composition.

`host.rs` owns a reactive winit event loop with `Wait` / `WaitUntil`, coalesced repaint deadlines, and stale-pass suppression. Layout and rasterization occur only when the scene is dirty. An OS expose can blit retained pixels without rebuilding the UI. Hidden/minimized windows skip layout, rasterization, and presentation while worker completion and data dispatch continue. Pending texture-manager changes are consumed on the next visible egui pass, so fonts/images survive restoration. Scene construction and rasterization share a counter because both occur together; presentations have their own counter.

`capture.rs` provides an isolated, finite render-save-exit path through the same UI and `host::rasterize` function. Captures contain the client area, not native chrome. The native `--diagnose` path separately measures a bounded visible/hidden/restored lifecycle with real GDI presentation and process CPU accounting. Capture success alone is never treated as evidence of idle efficiency or interactive responsiveness.

`theme.rs` defines shared text, surface, border, accent and warning roles, font sizes and spacing. Export remains outside the adjustment scroll region. Batch details start collapsed, and settings keep technical diagnostics and notices behind deliberate disclosure. Before/after labels and a directly draggable divider explain the comparison without an extra split-position slider.

`preferences.rs` atomically writes the small preferences JSON in the same per-user data directory as before. It migrates startup update checks, output format and quality from the former eframe RON map without changing that legacy file. Old window geometry/egui layout state is not imported. Failures are shown in Settings rather than silently claiming persistence.

`main.rs` owns UI state, two preview textures, a maximum 64-entry queue, and worker channels. Image decode, thumbnail generation, filters, full-resolution export and codecs run on one image worker with a one-entry command/result channel. The shared updater service handles HTTPS and preparation on a sleeping channel worker. File dialogs run on one short-lived helper thread at a time. Completion and changed progress values wake the event loop; no recurring busy/idle refresh is needed.

`worker.rs` retains at most one full decoded image. It drops the previous cache before loading another file, including after a failed load. Every preview carries its selected path, so a batch that changes the cache cannot accidentally render the wrong photograph. The UI serializes the batch and keeps controls frozen while processing, using a consistent setting snapshot for its jobs. A failed file is reported and the queue continues; cancellation stops scheduling subsequent jobs.

`engine.rs` validates parameters, dimensions, file size and input color declarations before large allocations. It applies decoder-provided orientation, then uses 8-bit RGBA buffers with linear-light math through a 256-entry lookup table. Edge-aware 3×3 smoothing is blended with the original and combined with color adjustment; optional sharpening uses another bounded RGBA buffer. Upscaling interpolates premultiplied linear RGB and alpha, avoiding color fringes from hidden pixels. Filtering keeps alpha unchanged. Input + intermediate + output + codec/preview allowances are included in the conservative allocation plan. This is not a hard whole-process memory cap; the OS, renderer, allocator, and codec overhead remain platform-dependent.

PNG metadata is inspected explicitly because the generic image decoder does not transform gamma, chromaticity, or cICP declarations. Unsupported unprofiled declarations are refused. RGB/grayscale ICC-tagged 8-bit input is transformed to sRGB with the pure-Rust `moxcms` engine before EXIF orientation. Profile parsing, LUTs and tone curves have explicit limits; conversion checks cancellation between rows and preserves alpha exactly. Profiles must match the decoded channel model; damaged or unsupported profiles are reported instead of silently ignored. Exports carry only normalized pixels and the PNG sRGB declaration; EXIF, GPS, custom profiles and other original metadata are not copied. JPEG output requires opaque input and uses the selected quality. The source file is never opened for writing.

Export encodes into a temporary file in the destination directory, flushes and syncs it, checks cancellation again, then uses no-clobber publication. An existing file or publication race fails instead of replacing another result. Filesystem/permission errors remain visible. Codec calls are not internally cancellable; temporary output is removed on error/cancel, except that abrupt process/power loss can leave a temporary file.

`updates.rs` supplies the canonical repository, installed product version, 150-MiB download limit, GUI PE subsystem and helper arguments to `rust-auto-updator`. The core checks stable semantic precedence, exact repository-bound assets, expected size, SHA-256 and PE headers/sections/entry point. Digest-only historical releases remain accepted; supplied checksum files are verified too. No download starts before the user's Download and install action. A verified `Prepared` value stays owned by the application until Install and restart succeeds at handoff. The helper waits for process exit and handles replacement/rollback/restart without touching preferences or photos. After a successful first native frame, cleanup acknowledges healthy startup; the helper preserves rollback files if startup cannot be established. Download cancellation is cooperative between reads, with bounded network timeouts. No live update installation was performed in this audit.

Settings include the compiled third-party notices with a virtualized text viewer, so a standalone executable carries its dependencies' notices without repeatedly laying out the entire license document.

`inference.rs` defines `LocalEnhancementBackend`, capability status, cancellation, model identity, license and tile-limit reporting. Only `UnavailableBackend` exists today. The deterministic pipeline never masquerades as that interface's learned output.


## Shared updater boundary

`rust-auto-updator` owns canonical release parsing, stable version precedence, checksum/digest and PE verification, cancellable download, staging, wait/replace/rollback/restart and cleanup. PhotoEnhancer supplies repository/version/product configuration and handles worker events without an update repaint timer. The native host skips rasterization while hidden, minimized or occluded; actual OS exposure paints can reuse the retained CPU bitmap. Image processing sends coalesced progress notifications rather than polling the unchanged UI every 150 ms.
